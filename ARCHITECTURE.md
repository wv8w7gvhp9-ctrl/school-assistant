# Архитектура первого этапа

## Выбранный стек

- **React 19 + TypeScript + Vite** — быстрый, строго типизированный mobile-first клиент.
- **vite-plugin-pwa / Workbox** — manifest, service worker и кэш ассетов для установки PWA.
- **Supabase** — Auth для родителя и детского устройства, Postgres, RPC и RLS для изоляции семьи и ролей; Edge Functions и планировщик уведомлений остаются следующим серверным этапом.
- **IndexedDB** — локальные снимки последних успешных детских данных для чтения без сети; `localStorage` не используется как подмена облачной синхронизации.
- **Идемпотентная офлайн-очередь** — действия ребёнка получают UUID, сохраняются в IndexedDB, проверяются по версии серверной записи и подтверждаются таблицей квитанций; повторный запрос не повторяет изменение.
- **Vitest** — модульные проверки бизнес-правил; e2e-инструмент будет добавлен вместе с первыми серверными сценариями.

Бизнес-правила будут вынесены из компонентов в доменные модули и серверные функции. Клиент получает только публичный Supabase anon key; service-role и VAPID private key остаются в защищённой серверной среде.

## Текущий контракт

Пять утверждённых детских экранов получают семейные данные через защищённые Supabase RPC. Родитель управляет расписанием, домашкой, книгами и кружками; ребёнок выполняет только разрешённые действия. Последний успешный детский ответ сохраняется в IndexedDB отдельно по ребёнку и фактической дате. Без сети доступно чтение снимка, а серверные кнопки честно заблокированы. Офлайн-очередь изменений ещё не объявляется готовой.

## Внешняя настройка

1. Supabase и публичные `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` настроены в Vercel.
2. HTTPS-домен Vercel используется для установленной PWA.
3. Для Web Push ещё нужно создать VAPID-ключи: публичный ключ — в Vercel, закрытый — только в секретах серверной функции.
4. Для расписания уведомлений нужен серверный планировщик в `Europe/Samara`; браузерный таймер не используется для закрытой вкладки.

Push пока не реализован и не имитируется. Офлайн-очередь внедряется вертикально: первым поддержан переход домашнего задания к проверке; дневник и рюкзак остаются следующими сценариями. Секреты не записываются в клиент или репозиторий.
