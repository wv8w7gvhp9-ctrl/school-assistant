# Архитектура первого этапа

## Выбранный стек

- **React 19 + TypeScript + Vite** — быстрый, строго типизированный mobile-first клиент.
- **vite-plugin-pwa / Workbox** — manifest, service worker и кэш ассетов для установки PWA.
- **Supabase (планируемый серверный контур)** — Auth для родителя, Postgres, RLS для изоляции семьи и ролей, Realtime, Edge Functions и планировщик уведомлений.
- **Vitest** — модульные проверки бизнес-правил; e2e-инструмент будет добавлен вместе с первыми серверными сценариями.

Бизнес-правила будут вынесены из компонентов в доменные модули и серверные функции. Клиент получает только публичный Supabase anon key; service-role и VAPID private key остаются в защищённой серверной среде.

## Контракт этого этапа

Пять утверждённых детских экранов решают задачу обзора школьного дня для ребёнка. Они используют вымышленные данные Миши из памяти процесса и не делают сетевых запросов. Фильтры, выбор дня и раскрываемые визуальные элементы являются безопасной навигацией по демо-данным. Действия, которые требуют сервера (отправка задания, рюкзак, дневник), недоступны: интерфейс не обещает сохранение или синхронизацию.

## Необходимая внешняя настройка для следующего этапа

1. Создать проект Supabase и задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` только в локальном `.env`/хостинге.
2. Настроить HTTPS-домен для установленной PWA.
3. Создать VAPID-ключи: публичный ключ в `VITE_VAPID_PUBLIC_KEY`, закрытый — только в секретах Edge Function.
4. Настроить серверный планировщик Edge Functions в `Europe/Samara`; браузерный таймер не используется для закрытой вкладки.

До этого подключение семьи, RLS, облачная синхронизация, push и отложенная очередь не реализованы и не имитируются.
