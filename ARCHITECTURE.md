# Архитектура первого этапа

## Выбранный стек

- **React 19 + TypeScript + Vite** — быстрый, строго типизированный mobile-first клиент.
- **vite-plugin-pwa / custom service worker** — manifest, кэш ассетов, обработка Web Push и открытие приложения по нажатию на уведомление.
- **Supabase** — Auth, Postgres, RPC и RLS для изоляции семьи и ролей; Edge Function отправляет Web Push, а `pg_cron` вызывает её каждую минуту.
- **IndexedDB** — локальные снимки последних успешных детских данных для чтения без сети; `localStorage` не используется как подмена облачной синхронизации.
- **Идемпотентная офлайн-очередь** — действия ребёнка получают UUID, сохраняются в IndexedDB, проверяются по версии серверной записи и подтверждаются таблицей квитанций; повторный запрос не повторяет изменение.
- **Vitest** — модульные проверки бизнес-правил; e2e-инструмент будет добавлен вместе с первыми серверными сценариями.

Бизнес-правила будут вынесены из компонентов в доменные модули и серверные функции. Клиент получает только публичный Supabase anon key; service-role и VAPID private key остаются в защищённой серверной среде.

## Текущий контракт

Пять утверждённых детских экранов получают семейные данные через защищённые Supabase RPC. Родитель управляет расписанием, домашкой, книгами и кружками; ребёнок выполняет только разрешённые действия. Последний успешный детский ответ сохраняется в IndexedDB отдельно по ребёнку и фактической дате. Без сети доступно чтение снимка. Поддержанные действия ребёнка помещаются в идемпотентную очередь и явно показываются как ожидающие отправки.

## Внешняя настройка

1. Supabase и публичные `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` настроены в Vercel.
2. HTTPS-домен Vercel используется для установленной PWA.
3. Реализация Web Push находится в проекте. До включения нужны VAPID-ключи: публичный ключ — в Vercel и Supabase, закрытый — только в секретах Edge Function.
4. Серверный планировщик и Edge Function настраиваются по `PUSH_SETUP.md`; браузерный таймер для закрытой вкладки не используется.

Push не имитируется: браузер регистрирует реальную подписку, серверная очередь защищена уникальным ключом события, а доставку выполняет только Edge Function. Офлайн-очередь поддерживает отправку домашки, последовательные отметки с отправкой рюкзака и полный черновик читательского дневника. Секреты не записываются в клиент или репозиторий.

Звёзды хранятся как неизменяемые серверные события. Обычные начисления защищены уникальной парой основания и его ID; ежедневная награда использует детерминированный ID ребёнка и даты. Техническая корректировка не переписывает историю, а добавляет отдельное событие через родительскую RPC с проверкой семьи, диапазона и неотрицательного итогового счётчика. Детское устройство читает историю только через привязанную активную сессию и сохраняет последний успешный снимок в IndexedDB.

Подключение детского устройства отзывается отдельной родительской RPC. Сервер проверяет неанонимную роль и принадлежность устройства семье, атомарно ставит временную отметку отзыва и отключает push-подписки этой детской сессии. Все детские RPC продолжают проверять активную запись `child_devices`, поэтому отозванная сессия не получает новые семейные данные. Уже сохранённый на физическом устройстве офлайн-кэш нельзя стереть удалённо; это ограничение явно показано родителю перед подтверждением.
